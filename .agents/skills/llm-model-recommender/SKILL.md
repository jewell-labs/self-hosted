---
name: llm-model-recommender
description: Recommend at most one llm weight that fits the host holding the weights, trading some quality for speed or a capability, then sample it and keep or remove it.
---

Call `llm.models`, `llm.usage`, and `llm.config` on the host that holds the weights before choosing. When the agent sits on another machine, the limits and the library still come from that host. Configure a language-model file. If that call returns an error, configure one other language-model file from the library and keep both results. A projector, drafter, MTP sidecar, patch file, or other sidecar is not a candidate. `home/policy.json` is the disk reserve, the download cap, and the probe text. Read two current public sources and record each URL and date. One ranks model quality. The other ranks speed. Do not invent a leaderboard number, a speed, or a size.

The size class is that host's `memGb`. A host-class file is one single `.gguf` under the resident ceiling. When `memGb` is above 8, that file is also larger than 8 GiB. An 8 GB-class file is an alternate for a smaller machine. It is the download only when no host-class file passes max, disk, and resident. Measure the smallest 4-bit single file that fits the ceiling, preferring `Q4_K_M` when the repo publishes one. A smaller quant is that alternate, not the choice, when the 4-bit file fits. A shard set is not a single file.

A challenger may score below the best resident language model. Take a lower index when the higher one does not fit, or when the lower one is faster than that resident or adds a capability the higher one lacks. Prefer the higher published index when both gain the same thing. A file with no published index does not outrank a published one. A smaller file than the resident is the speed gain when the source publishes no tokens per second. Capabilities are tool use, code, vision, and a longer context. Record the gain. An official repo with no `.gguf` does not end the search. Look up one quant repo. For the chosen file and one alternate, write four marks from that size: max, disk, memory, and resident. Label each one `resident`, `sidecar`, or `absent` by the role check. Recommend at most one single-file GGUF that passes every mark. It has to fit `maxDownloadBytes`, `freeBytes - reserveBytes` of disk, currently free memory, and one resident model on this host's `llmProfile`. The download reads the whole file into memory before it renames. A file that misses any mark is not a recommendation. A file already in the library is not a new one. An empty decision catalog lists every file as `llm`; a decision weight is not a chat candidate and is not something to replace. Measure five host-class models from the speed source, and one 8 GB-class file that is not the download while a host-class file exists. Search the quality board from the top until one single-file GGUF is under the resident ceiling or five models have been checked. Record each file's bytes, or skip it because this run already measured that repo, or because its listing has no single `.gguf`, or because this run's search returned no public repository for that name. If none qualifies, stop. Do not download, sample, or remove.

Download a qualifying file with `llm.download` from a Hugging Face `org/name` only, into the directory the running router serves. If the library and that directory differ, stop.

Call `llm.sample` only for that downloaded file, with `seed` set to the UTC hour plus the file name. The probes are chat completions. The tool does not start the server. A model that does not serve chat fails them. That failure is not a quality result, so do not remove the weight because of it.

`keep: true` means leave the download. `keep: false` after the probes actually ran means call `llm.remove` on that downloaded file before you finish. Call `llm.remove` on a fleet file only when `replace` names it. Do not remove a decision weight.

After the comparison, score the recommendation from its record. One point per check. Report the total out of 10 and every miss by name.

- limits: `freeBytes`, `reserveBytes`, `maxDownloadBytes`, free memory, `memGb`, and the profile or the slot count, from this run on the host that holds the weights.
- board: both source URLs and the as-of date on each page. One page ranks quality. The other ranks speed.
- baseline: the best resident language model, its bytes from `models`, and its quality index. A challenger below that index passes when the record names the speed or capability gained. A config error counts only together with a second language-model config result.
- measured: every size used to reject or choose a challenger is a byte count from a single-file GGUF listing or a content-length fetched in this run. An official repo with no `.gguf` still needs one quant-repo lookup. A listing fetched in this run with no single `.gguf` file is a measured rejection.
- coverage: five host-class models from the speed source, one 8 GB-class file that is not the download while a host-class file exists, and the quality-board search from the top until one single-file GGUF is under the resident ceiling or five models have been checked. Each is measured, or skipped because this run already measured that repo, or because its listing has no single `.gguf`, or because this run's search returned no public repository for that name.
- fit: the chosen file and one alternate each have four marks from the single-file size in the record. A listing with no single `.gguf` fails every mark. Max passes at size ≤ `maxDownloadBytes`. Disk passes at `freeBytes - size` ≥ `reserveBytes`. Memory passes at size ≤ free memory. Resident passes at size < `memGb` × 2^30.
- action: `none` when no measured single-file GGUF passes every mark. Otherwise one download. The record names the host-class file that would be the download and, when its quality index is below the resident, the speed or capability gained. The 8 GB-class file stays the alternate while that host-class file exists.
- tools: `none` means download, sample, and remove were not called. A download is sampled. Removal follows `keep` and `replace` only after the probes ran.
- role: catalog length is recorded. For the chosen file and the alternate, the record says `resident`, `sidecar`, or `absent`. A library file whose name contains the model slug is `resident` when its bytes are in the same order of magnitude as the listing, and `sidecar` when they are not. Resident is not a new download. A sidecar is not the baseline.
- arithmetic: the reported total equals the number of checks that passed.
